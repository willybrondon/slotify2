# Prompt 4 — Le SQUIRE de Skedisy

**Sample ancré :** 329 salons afro pertinents IDF · avis Google API · crawl sites · ranking SQUIRE Prompt 3  
**Date :** 2026-09-11  
**Posture :** fondateur, pas consultant diplomatique.

---

## Question centrale

> Quel problème est assez douloureux, fréquent et économique pour construire un produit vertical Skedisy ?

**Réponse courte :**  
Le salon ne sait pas **verrouiller un rendez-vous afro long** (3–6h) sans passer par un chaos WhatsApp/DM : pas de qualification structurée → durée/prix faux → pas d’acompte clair → créneau brûlé ou cliente en colère.

Ce n’est **pas** « manquer de réservation en ligne ».  
C’est **manquer d’un système de conversion de demande en engagement** adapté au *projet* capillaire afro.

---

## Comparatif brutal vs outils existants

| Acteur | Ce qu’il fait bien | Ce qu’il ne résout PAS (afro IDF) |
|---|---|---|
| **Planity** | Agenda + catalogue + paiement partiel | Pas de diagnostic texture/mèches/photo ; durée catalogue fixe ; devis « à partir de » ; sous-fit projet 3–6h |
| **Fresha / Booksy** | Idem beauté généraliste | Même underfit vertical |
| **Treatwell** | Marketplace acquisition | Ne structure pas l’ops salon ni la qualif |
| **Google** | Demande (fiche / avis) | Amène l’appel ; zéro qualification |
| **Instagram** | Acquisition visuelle | DM = chaos ; pas devis/durée/acompte |
| **WhatsApp** | Canal universel FR | Inbox non structurée = « OS » par défaut ; perte d’info ; pas d’anti-no-show natif |

**Preuves sample :** 249/329 sans système booking classique ; 161/329 acompte non visible sur site ; 90 salons avec avis qualité/mèches ; 78 prix ; 57 durée ; 54 malentendu prestation ; même chez Planity (39), des douleurs avis persistent.

## A. Les 5 meilleurs wedges

### W1 — Conversion demande → Qualif → Devis/durée → Acompte *(CHOIX)*

| Critère | Verdict |
|---|---|
| 1. Spécifique afro ? | **Oui** — projet multi-heures, variables (texture, longueur, mèches) |
| 2. Fréquent ? | **Oui** — structurel sur ~100% du vertical ; WA/DM dominant |
| 3. Douloureux ? | **Oui** — créneaux longs brûlés + litiges + charge owner |
| 4. Temps/argent ? | Un no-show / mal-estimé = **demi-journée** perdue + risque 1★ |
| 5. Outils existants ? | Non — Planity = agenda ; WA = bricolage |
| 6. Pourquoi changer ? | « Je récupère 3–6h et je dors » |
| 7. MVP | Lien / flow : photo + questions → devis + durée → acompte → créneau |
| 8. Data | Photos, textures, durées réelles, taux acompte, no-show |
| 9. Moat | Modèle de durée/prix afro IDF propriétaire |
| 10→11 | Historique cliente → CRM → planning staff → OS |

### W2 — Estimation durée réelle (anti-retard)

Spécifique oui, fréquent (avis durée/attente), douloureux oui.  
**Faiblesse :** feature sans cash capture ; difficile à vendre seule. Mieux en **brique de W1**.

### W3 — Devis prix verrouillé (anti-surprise)

Spécifique oui (suppléments mèches/longueur), 78 salons avis prix.  
**Faiblesse :** sans acompte + créneau, le devis reste un PDF. Sous-wedge de W1.

### W4 — Remplacer WhatsApp comme OS (inbox unifiée)

Douloureux, fréquent en FR.  
**Faiblesse :** moins *spécifique* afro (tous les SMB). Concurrent = CRM générique. Skedisy gagne si l’inbox est **métier afro** (W1), pas une messagerie de plus.

### W5 — Anti-no-show / acompte seul

Économique énorme, mais **preuve no-show faible** dans les avis API (n=5). Acompte sans qualif = friction inutile. Doit suivre le devis (W1).

**Rejetés pour wedge #1 :** fidélisation/réactivation (preuve faible), RH indépendantes (non prouvé), hygiène (pas SaaS), « un autre Planity » (suicide).

## B. Fiches des 5 wedges

### 1) W1 — Qualif → devis/durée → acompte ✅

- **Problème :** Impossible de transformer une demande (WA/IG/Google) en RDV afro engagé sans chaos manuel.
- **Utilisateur :** Owner / manager / coiffeuse solo qui gère l’inbox.
- **Moment exact :** Entre le premier message (« je veux des box braids ») et le créneau bloqué.
- **Solution actuelle :** Allers-retours WA + photos + « je te dis le prix le jour J » ± Planity pour l’agenda.
- **Solution Skedisy :** Un parcours guidé afro qui sort : prestation clarifiée, durée estimée, prix/devis, acompte payé, créneau tenu.
- **vs Planity :** Planity part du catalogue ; Skedisy part de la **demande et du diagnostic**.
- **vs WhatsApp :** Même canal d’entrée possible, mais états métier (qualifié / devis / payé) au lieu d’un fil de chat.
- **vs Fresha/Booksy :** Idem Planity — agenda généraliste.
- **Pourquoi il paie :** Réduit no-show, litiges prix, retards chaîne, heures owner.
- **Difficulté lancement :** Moyenne — besoin d’intégration paiement + UX photo ; go-to-market via salons déjà sur WA (pas besoin de migrer tout l’agenda jour 1).

### 2) W2 — Durée réelle

- Moment : pendant la journée quand le 2e RDV décale.
- Skedisy : estimateur durée (texture/longueur/volume/photo).
- vs Planity : durée fixe catalogue.
- Paie ? Faible seul ; fort avec W1.
- Lancement : difficile sans data durée réelle (chicken-egg) → se nourrit de W1.

### 3) W3 — Prix verrouillé

- Moment : en salon quand le prix « change ».
- Skedisy : devis signé avant créneau.
- vs WA : oral non traçable.
- Paie ? Moyen seul ; fort avec acompte.

### 4) W4 — Inbox métier

- Moment : 20 messages non classés le soir.
- Skedisy : inbox avec pipeline afro.
- Risque : paraître « encore un outil message ».
- Ne lancer **que** si collé à W1.

### 5) W5 — Acompte anti-no-show

- Moment : cliente qui ne vient pas sur un créneau 4h.
- Skedisy : acompte conditionnel au devis.
- Preuve volume no-show faible dans sample → ne pas vendre « anti-no-show » en slogan #1 ; le vendre comme **conséquence** du funnel W1.

---

## C. UNE SEULE opportunité (choix)

### **W1 — Qualif → devis/durée → acompte**

**Pourquoi celle-là et pas les autres :**

1. C’est le seul wedge qui est **à la fois** spécifique afro, prouvé dans les données, et **monétisable dès le jour 1** (le pro paie pour protéger des créneaux de plusieurs heures).
2. W2/W3/W5 sont des **sous-produits** de W1, pas des produits.
3. W4 sans W1 = Slack pour coiffeuses : commodité, pas moat.
4. Construire un Planity-bis est la façon la plus sûre de **mourir** contre une marque déjà installée en France.

**Phrase :**

> **Skedisy ne devrait pas être un autre logiciel de réservation pour les salons afro. Skedisy devrait être le système qui transforme une demande WhatsApp/Instagram en devis, durée et acompte — avant de bloquer 3 à 6 heures.**

## Roadmap

### PHASE 1 — Problème initial (0–4 mois)
- MVP : lien Skedisy partagé en WA/IG/bio  
- Questions + upload photo  
- Devis + estimation durée  
- Acompte (Stripe/Payplug)  
- Confirmation créneau (manuel ou sync calendrier minimale)  
- Cible : 15–30 salons afro IDF early adopters  
- Success metric : % demandes → acompte payé ; baisse no-show déclarée

### PHASE 2 — Produit indispensable (4–10 mois)
- Templates prestations afro (tresses, locks, tissage, lace…)  
- Règles suppléments (longueur / masse / mèches fournies ou non)  
- Rappels J-1 + politique annulation  
- Tableau « demandes du jour » pour l’owner  
- Metric : Skedisy utilisé **chaque jour** même si Planity reste pour une partie du planning

### PHASE 3 — CRM vertical (10–18 mois)
- Fiche cliente : photos avant/après, prestations, mèches, durées réelles  
- Historique litiges évités / devis acceptés  
- Relances entretien (locks, reprise tissage) **basées sur le cycle réel**  
- Metric : LTV cliente trackée dans Skedisy

### PHASE 4 — Operating System salon (18–30 mois)
- Planning multi-coiffeuses alimenté par durées **apprises**  
- Stock / consignes mèches  
- Commissions / indépendantes  
- Pilotage : taux remplissage, no-show, panier moyen  
- Skedisy = source de vérité ops, pas un gadget booking

### PHASE 5 — Expansion communautés beauté (30+ mois)
- Même wedge « projet beauté long + supply + acompte » :  
  - afro hors IDF / France  
  - braids/locs US/UK si pattern similaire  
  - niches proches (nails complexes, bridal afro, etc.) **seulement** si le funnel qualif→devis→acompte se réplique  
- Ne pas diluer en « Planity pour tout le monde »

---

## Anti-roadmap (ce qu’on ne fait pas en Phase 1)

- Marketplace grand public type Treatwell  
- Feature parity Planity (agenda complet, POS, etc.)  
- App cliente lourde avant que le funnel pro ne marche  
- Fidélisation points / coupons  
- Scrape Instagram / lecture DM privés
